# Steward · 整体架构方案

> 状态：已确认（2026-10-16）。配套阅读：`docs/PRD-第一阶段.md`（需求与验收场景）。

## 1. 总架构

```
你（微信）
   │
龙虾（OpenClaw）—— 脑子在这里：理解自然语言、解析成结构化数据
   │
   ├── MCP stdio → deputy        事业助手（已有，不动）
   │
   └── MCP stdio → steward      生活管家（本项目，统一入口）
         │
         ├── 本地 SQLite「生活流水」events      ← 运动/饮食/身体/通勤 + 兜底
         │
         └── MCP client → credi-insights MCP   ← 财务（数据留在那边不复制）
```

**职责边界一句话**：龙虾负责"听懂"，Steward 负责"记住和算清"，
credi-insights 负责"财务记录与分类记账"。

## 2. 模块划分（2026-10-16 确认）

Steward 按**模块**组织。地基是一张通用事件表，每个模块在其上注册自己的
类型校验、汇总口径和 MCP 工具；财务模块例外——它不写本地库，读上游。

| 模块 | 覆盖 | 事件类型 | MCP 工具 |
|---|---|---|---|
| 🏃 **fitness** 运动 | 跑步/走路/游泳/健身/骑行/徒步/球类 + 运动目标 | `workout` | `log_workout` · `query_workouts` · `set_goal` · `goal_progress` |
| 🍜 **diet** 饮食 | 吃了什么（可带花费） | `meal` | `log_meal` · `query_meals` |
| ⚖️ **body** 身体 | 体重（未来体脂等也归这里） | `body` | `log_body` · `query_body` |
| 🚇 **commute** 通勤 | 上下班打卡 | `commute` | `check_in` · `query_commute` |
| 💳 **finance** 财务 | credi-insights 账单的分析与复盘（记账/分类在 credi-insights 完成） | —（不落本地） | `spending_summary` · `spending_trend` · `subscriptions` |
| 🧺 **通用兜底** | 其他任何事情 | 任意 type | `log_event` · `query_events` |

**通用兜底的意义**：未建模块的事（"配了颗新牙 800 块"）随时可以用通用工具
记录，永不被 schema 卡死；未来某个 type 记多了，升级成独立模块即可。

## 3. 通用流水（core）

```sql
events(id, type, occurred_at, raw_text, payload JSON, created_at)
```

- `type`：事件类型（workout/meal/body/commute/…任意）
- `raw_text`：用户原话，永久保留
- `payload`：龙虾解析后的结构化数据（各模块定义自己的 schema 约定）
- 各模块 payload 约定在各模块的 OpenSpec change 中定义，不在本文维护

## 4. 财务模块（finance）

**原则：财务记录与分类记账由 credi-insights 完成（其 AI 分类已就绪），
Steward 只读不写、不复制数据、不重复造分类。**

- credi-insights 已有 stdio MCP server（`mcp-server.ts`：读卡片/交易/分类/同步）。
- Steward 作为 MCP client 挂载（stdio 子进程，需注入 `DATABASE_URL`，部署文档写清 Node 依赖）。
- Steward 封装面向复盘的语义：月度消费汇总、分类占比、趋势对比、订阅/固定支出识别。
- 月度复盘时与本地流水（如有）合并看全貌。

## 5. 目标管理（goals，属 fitness 模块）

- 第一阶段只做**周期型**：`kind=workout`，`metric=distance/frequency/duration`，
  `period=week/month`（月跑量 50km、每周运动 3 次、月运动 12 次）。
- 进度从流水实时计算，不存快照；同 `(kind, metric, period)` 至多一个进行中目标。
- 截止日型目标、其他模块目标 → 未来演进。

## 6. Change 路线图（每个走一次 OpenSpec 门禁）

| # | Change | 内容 |
|---|---|---|
| 1 | `core-events` | 通用流水地基：events 表 + `log_event`/`query_events` + 未知类型放行 |
| 2 | `mod-fitness` | workout 校验/汇总 + 4 工具 + goals —— **竖切样板，确立模块接入模式** |
| 3 | `mod-basics` | diet / body / commute 三个薄模块（复制样板模式） |
| 4 | `mod-finance` | credi-insights MCP 接入 + 财务分析工具 |
| 5 | `review` | 周期复盘生成（合并 events + goals + credi-insights） |
| 6 | `insights` | 趋势与异常主动发现 |

## 7. 边界（第一阶段不做）

- 自然语言解析（龙虾侧职责，Steward 只收结构化 payload + 原文）
- 医疗健康、Travel、Family、情感、投资分析（PRD 第 6 节）
- 财务记录/分类记账的重做（credi-insights 职责）
- 通知/推送主动打扰（insights 只做到"问的时候能答 + Review 里主动指出"）
- 多用户、部署到公网（单机 Mac mini，数据不出墙）
