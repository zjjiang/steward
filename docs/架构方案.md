# Steward · 整体架构方案

> 状态：草案（2026-10-16），经用户确认后作为第一阶段实施依据。
> 配套阅读：`docs/PRD-第一阶段.md`（需求与验收场景）。

## 1. 总架构

```
你（微信）
   │
龙虾（OpenClaw）—— 脑子在这里：理解自然语言、解析成结构化数据
   │
   ├── MCP stdio → deputy        事业助手（已有，不动）
   │
   └── MCP stdio → steward      生活管家（本项目，统一入口）
         │
         ├── 本地 SQLite「生活流水」events + goals   ← 需求 1/3/4
         │
         └── MCP client → credi-insights MCP        ← 需求 2
             （信用卡账单、交易、分类、订阅，数据留在那边不复制）
```

**职责边界一句话**：龙虾负责"听懂"，Steward 负责"记住和算清"，credi-insights
负责"信用卡账单"。

## 2. 核心抽象：通用生活流水（events）

Steward 的地基是一张通用事件表，**不是** fitness 专用表：

```
events(id, type, occurred_at, raw_text, payload JSON, created_at)
```

- `type`：事件类型（workout / meal / body / commute / expense / …未来扩展）
- `raw_text`：用户原话，永久保留（"今天跑了 8km"）
- `payload`：龙虾解析后的结构化数据（按 type 有各自的 schema 约定）

第一阶段的 type 及 payload 约定：

| type | 用途 | payload 关键字段 |
|---|---|---|
| `workout` | 走路/跑步/游泳/健身/骑行/徒步/球类 | `sport, duration_min?, distance_km?, notes?` |
| `meal` | 吃了什么（可带花费） | `meal(breakfast/lunch/dinner/snack), desc, cost?` |
| `body` | 体重等身体记录 | `weight_kg` |
| `commute` | 上下班打卡 | `direction(in/out)` |

查询与统计工具同样通用：`query_events(type, date_from, date_to)` 返回明细 +
按 type 的汇总（workout 汇总公里数/时长/次数，body 返回序列与变化，…）。

**扩展方式**：未来加"其他事情"（travel、家庭、任何生活事件）= 定义新 type 的
payload 约定，表结构与 MCP 工具不重构。第一阶段不定义的 type 也允许记录
（payload 自由 JSON），保证输入永远不被 schema 卡死。

## 3. 四个需求的落点

| # | 需求 | 落点 |
|---|---|---|
| 1 | 走路/游泳/吃了啥/体重 | 本地 events：`workout` / `meal` / `body` |
| 2 | 信用卡记账与分类 | **credi-insights 开放 MCP**（其 `mcp-server.ts` 已具备卡片/交易/分类工具），Steward 作为 MCP client 集成；本地只有零星现金支出快记（`expense`） |
| 3 | 上下班打卡 | 本地 events：`commute`（一行打卡，月底自动出通勤统计） |
| 4 | 其他事情 | 未来新 type，层已预留 |

## 4. credi-insights 接入设计（需求 2）

**原则：数据不复制、不直连库。Steward 是 credi-insights 的上游消费者。**

- credi-insights **已有** stdio MCP server（`mcp-server.ts`：读卡片、读交易、
  分类规则、IMAP 同步）——"开放 MCP"已满足，无需大改。
- Steward 作为 **MCP client** 挂载它（stdio 子进程，需注入 `DATABASE_URL`，
  部署文档写清依赖 Node 环境）。
- Finance 工具在 Steward 侧封装为面向复盘的语义：
  `spending_summary(月份)` / `spending_by_category` / `subscriptions()` /
  `spending_trend(近N月)` —— 内部调用 credi-insights 工具做聚合，
  **月度复盘时与本地 `expense`/`meal` 快记合并出全貌**（账单 + 现金）。
- 记账与分类本身仍在 credi-insights 内完成（它的分类规则 + AI 分类），
  Steward 不重复造分类，只在复盘语义上做"值得注意的变化"判断。

## 5. MCP 工具清单（分阶段）

**Change 1（life-log）**：
`log_event` · `query_events` · `set_goal` · `goal_progress`

**Change 2（finance-integration）**：
`spending_summary` · `spending_trend` · `subscriptions` · 本地 `expense` 快记

**Change 3（review）**：
`weekly_review` / `monthly_review` —— 合并 events + goals + credi-insights 数据，
输出有判断、有行动建议的复盘。

**Change 4（insights）**：
趋势与异常的主动发现（连续几周运动下降、某类消费高于基线、新固定支出…）。

## 6. 目标管理（goals）

```
goals(id, kind, target, period, metric, status, created_at)
```

- 第一阶段只做**周期型**目标：`kind=workout`，`metric=distance/frequency/duration`，
  `period=week/month`（如：月跑量 50km、每周运动 3 次、月运动 12 次）。
- `goal_progress` 返回：当前完成 / 还差多少 / 按时间进度推算是否正常。
- 截止日型目标、非运动目标 → 未来演进，表结构已兼容。

## 7. 边界（第一阶段不做）

- 自然语言解析（龙虾侧职责，Steward 只收结构化 payload + 原文）
- 医疗健康、Travel、Family、情感、投资分析（PRD 第 6 节）
- 通知/推送主动打扰（Change 4 只做到"问的时候能答 + Review 里主动指出"）
- 多用户、部署到公网（单机 Mac mini，数据不出墙）
